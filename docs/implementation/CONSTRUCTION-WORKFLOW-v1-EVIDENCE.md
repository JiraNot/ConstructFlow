# Construction Workflow v1 — Application-Level Evidence

Status: Application-level proof complete when the companion CI test is green and merged. Native SketchUp/LayOut acceptance remains separate.

## Purpose

This implementation note records the evidence boundary for the coordinated Extension construction package. The authoritative behavior remains in `docs/architecture/EXTENSION-CONSTRUCTION-WORKFLOW.md` and the owning domain specifications.

## Proof path

The companion `test/extension/construction_workflow_v1_proof_test.rb` composes a representative package through the public `ConstructionWorkflowRunner` path:

`Extension → semantic package state → ConstructionTakeoff → Strict ConstructionQualityGate → Drawing Issue Set → scene refresh → ConstructionOutputSettlement → ConstructionCurrentnessAudit → native-export boundary → construction output state → ConstructionIssueHistory`

The semantic package contains current objects for:

- Existing Architecture host context;
- Extension-generated Architecture wall and host Opening/demolition scope;
- approved Structure column and foundation;
- Roof and Roof-owned gutter;
- reviewed rainwater outlet evidence connected to an in-scope Drainage downpipe;
- Surface;
- Interior cabinet run;
- Electrical luminaire.

The proof also seeds a Structure object generated by a different Extension and asserts that it does not enter the selected Extension's Structure drawing scope or takeoff.

## Drawing package evidence

The representative issue set requires and refreshes:

- `A-100` — Architecture Demolition;
- `A-101` — Architecture Construction;
- `S-101` — Structure;
- `R-101` — Roof;
- `P-101` — Plumbing/Drainage;
- `L-101` — Surface/External Works;
- `I-101` — Interior/Joinery;
- `E-101` — Electrical.

All requested source IDs must be reported as rendered before drawing settlement is complete. Currentness then compares those refreshed scopes against the post-settlement Smart Object graph.

## Publication evidence

The proof requests publication through a fake native LayOut boundary and requires the workflow result to reach `exported`. It verifies:

- Strict QA is publishable;
- quantity settlement is complete;
- drawing settlement is complete;
- currentness is `current` and publishable;
- output-state evidence records `exported`;
- issue history records revision, LayOut path and PDF path;
- publication is invoked once for the current issue set.

The fake native boundary is intentional. It proves that application orchestration cannot bypass QA/settlement/currentness and that export evidence flows into document-control history. It does **not** prove native LayOut API behavior.

## Evidence not claimed

This proof does not replace real-application acceptance for:

- SketchUp save/close/reopen identity persistence;
- native Undo/Redo and copy identity behavior;
- real interactive handles/tools;
- native scene/tag/style persistence;
- real LayOut template/viewport creation and PDF export.

Those remain explicit native acceptance tasks and must not be inferred from pure-Ruby CI.
