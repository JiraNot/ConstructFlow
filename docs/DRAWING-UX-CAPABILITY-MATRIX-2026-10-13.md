# Drawing UX Capability Matrix — 2026-10-13

This matrix maps the main model families to their current canvas workflow, edit path, and the next acceptance target. Drawing tools create persistent Smart Objects through the same `CommandBus` used by Workbench commands; generated objects retain UUID identity and use the active renovation phase defaults.

## Implemented interaction contract

- Polygon tools share the slab drafting path: click points, use live dimensions and angle constraints, close at the start, double-click, or press Enter. Escape cancels the pending shape.
- Two-point tools share the line drafting path: click a start and end, constrain the second point with Shift, type a length/angle, and press Enter. Escape cancels without creating an object.
- Point tools place at the active snap and accept Enter from the dynamic dimension input.
- Roof and domain edits use `UpdateRoof`, `EditPipeRoute`, `UpdateElectricalFixture`, `UpdateCabinetRun`, and `UpdateMouldingRun`; they are undoable and retain object UUIDs.
- Roof drawing switches to a dedicated roof plan with architectural context. Roof footprints stay out of floor plans; the roof plan supports selection, vertex editing and the roof inspector, while the framing discipline displays catalog-resolved rafters, purlins and trusses.
- The roof inspector adjusts a uniform perimeter overhang and starts the shared polygon opening tool in roof plan. Openings are checked for containment/overlap and removed from roof mesh triangles and covering takeoff; gutter lengths, catchment area and pipe locations follow the eave outline. A concave roof generates a shallow 3D valley-gutter channel and a separate length takeoff. Rule 50 measures eaves to surveyed parcel pegs and reports insufficient data when neither a survey boundary nor an explicit measured offset exists.
- Pipe route properties can insert a bend at a segment midpoint, remove interior bends, connect either endpoint to a compatible manhole/septic tank or plumbing pump-bypass assembly, and edit intermediate elevations. Selected intermediate nodes show draggable plan grips; gravity-route previews recalculate intermediate elevations when datums are known and reject edits that violate known endpoint inverts or collapse adjacent nodes. Unknown connected inverts are preserved and reported as unknown instead of being fabricated.
- `AssignFixtureToCircuit` is one model command: it updates both the fixture's `circuit_id` and each affected circuit's `device_ids`, validates breaker load, and gives the complete reassignment one undo/redo step. Switch properties expose light-only control links through the same fixture validator.

## Direct manipulation contract

- Plan dragging is non-destructive until release. A translucent candidate is drawn over the committed object; blue indicates the latest valid command-bus preview and red indicates a rejected candidate. The original geometry stays in place during the gesture.
- Every pointer move derives candidate commands from the gesture's original model state. Validation is sampled during movement and repeated synchronously on release; only a valid candidate is dispatched as one undoable command batch. `pointercancel` discards the candidate without changing the project.
- The plan canvas applies the same preview, validation and commit path to walls, openings, columns, foundations, beams, grids, room separators, slab/floor/ceiling/roof/room boundaries, stairs, electrical fixtures, cabinets, mouldings, pipe routes, manholes, septic tanks, pump bypasses, LED runs and bathrooms. Shift selection supports group translation while preventing hosted openings and supported footings from being moved twice.
- Type-specific plan grips keep their semantic operation: openings resize from one jamb, rectangular column/footing corners keep the opposite corner fixed, stairs expose width and straight-run grips, and connected route/opening/beam geometry retains its host or node relationship.
- Slab edge grips move one straight boundary edge parallel to itself; adjacent corners stay on their neighboring edges, existing voids remain attached to their model coordinates, and command validation rejects edits that invalidate the polygon. A selected sloped slab shows a draggable drainage arrow. A supported two-slope gable shows a draggable ridge line; changing its position updates opposing pitches while preserving peak height.
- Selected hip roofs show facet seams in plan: the primary ridge uses a square grip, hip lines use blue dashed strokes, and valleys at reflex footprint corners use orange dotted lines with diamond grips. Dragging a seam grip adjusts the pitches on its two adjacent facets, previews the candidate through the shared validation/ghost path, and commits as one `UpdateRoof` undo step.
- Elevation movement and supported resize grips use the same validate-on-release transaction. Wall, opening, beam, column, slab/floor/ceiling and roof grips map to their own dimensions or datums; side grips do not alter vertical dimensions, and top/base grips do not translate objects horizontally. Elevation previews show candidate bounds while the original model remains visible.
- A hosted foundation follows its column; an independent foundation can move directly. The structural command validates this relationship and both paths remain undoable.

## Remaining interaction risks

- Elevation preview is currently a translucent candidate bounding rectangle. Family-specific rotated outlines and fully regenerated hosted geometry are shown more accurately in plan; the elevation ghost can be refined to project the candidate representation itself.
- Elevation multi-selection currently supports box selection, but dragging one member does not yet translate the full selected set as a group.
- Multi-click pipe routing, fittings, visible circuit paths and conduit geometry remain separate feature work, as do chained wall junction cleanup, continuous-beam break/merge, structural valley framing, roof family/type catalogs, and cabinet/MEP type catalogs.
- The preview uses the existing command validator and geometry services; large-project snap/search performance still needs a measured acceptance run at 5,000+ objects and a spatially indexed snap candidate path.

## Cross-view acceptance

1. Draw gable, hip and concave roofs; drag ridge/hip/valley grips and confirm peak elevation behavior. Add an overhang and opening, verify the outline and mesh in plan/3D/elevation, check covering/gutter/downpipe/valley-gutter quantities, and compare eave setback with a surveyed parcel.
2. Offset each edge of a slab and drag its slope arrow; confirm the arrow and percentage preview update, the roof/slab edits remain undoable, and a void that would cross the edited boundary is rejected without moving the committed slab.
3. Draw a gravity route and a cold-water route; add and move bends, connect compatible endpoints, and confirm invalid gravity grades or network connections are rejected while previews preserve the last committed route.
4. Place each electrical fixture kind; assign/unassign and transfer loads between circuits; confirm breaker overload rejects atomically, one undo restores both references, and switches can control only light fixtures.
5. Draw a cabinet and moulding run; rotate the cabinet with its plan grip and drag the moulding endpoints; confirm the cabinet anchor/dimensions and both UUIDs remain stable while geometry, cut list or quantity output updates.
6. Repeat roof, slab, route, fixture, cabinet and moulding create/edit/delete through undo/redo and project save/load; inspect plan, framing, elevation and 3D for view-specific visibility and stale geometry.
