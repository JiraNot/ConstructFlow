# ConstructFlow v1.0 Release Readiness

Status: Draft release gate, 2026-10-18. This document defines the release bar for the first supported standalone ConstructFlow release. It complements the active sequencing in [`../ROADMAP.md`](../ROADMAP.md); it does not claim that the entire Master Blueprint is complete.

## Product promise

ConstructFlow v1.0 is a tablet-first standalone workbench for surveying and editing small residential renovation/extension projects. A user must be able to start or import a project, author and adjust a supported architectural model, create/edit reusable families, save and reopen the project, and produce the supported drawing and quantity outputs.

The release must describe supported object families and file compatibility honestly. Thai code checks are input-dependent design aids. Generated structural details are not licensed engineering approval, and generated permit sheets are not automatically permit-ready.

## Release gates

Every gate needs a named reviewer, dated evidence, and a passing result on the release candidate. A feature existing in source code or a unit test passing is not, by itself, release evidence.

## Tablet acceptance script

Run these steps on each target device without an attached keyboard. Repeat core placement/editing with finger and stylus if the device supports both.

1. Open the project and reach the plan view; identify current level/view and change them.
2. Place a wall, move and resize it by dragging, then enter a precise dimension through the visual dimension control.
3. Place and adjust a grid line by dragging; verify its dimension updates and can be set precisely.
4. Place an opening hosted in the wall. When objects overlap, choose the intended object without accidentally selecting a ceiling or slab.
5. Use snapping and the distance tool to place a point or line accurately; cancel a partial operation and confirm the model is unchanged.
6. Open object properties, change a common parameter, Undo and Redo, then close the panel without losing canvas context.
7. Save, close/reload the app, reopen the same project and confirm the edited geometry, UUIDs, dimensions and selection-independent state.
8. Export a drawing/PDF and review it at actual A3 print scale.

Record each step as Pass, Fail, or Blocked, with a short note and evidence. A blocked result is not a pass.

## Scope exclusions for the first release

The v1.0 claim does not require every domain and every roadmap item. Unless separately proven and explicitly included in the supported matrix, exclude: complete Revit parity; arbitrary binary DWG writing/round-trip; full MEP coordination; automatic legal/permit approval; licensed structural engineering; cloud collaboration; and universal editing of every imported mesh/CAD entity. Keep project data portable and preserve stable identity for the supported workflows.

## Release decision

The release owner may label a build `v1.0.0` only when all required gates are Pass and the tablet and real-project gates have named reviewers. If the real project or supported hardware is unavailable, ship only as preview/beta and list the missing evidence. Do not convert missing evidence into an assumed pass.

Preliminary tablet evidence (2026-10-18): Chromium touch emulation at 768×1024 and 1024×768 exercised wall placement/cancel, Inspector open/edit/close, tool group selection, and slab polygon finish. The portrait Inspector now uses the full workspace width; common level and phase labels are short Thai text. The plan canvas backing resolution now follows device pixel ratio, capped at 2, while model transforms continue to use CSS pixels. A coarse-pointer rule preserves touch-sized controls and starts with the Inspector closed on wide CSS viewports. In the current browser at DPR 1.25, canvas backing size was 1087×804 for an 869×643 CSS-pixel viewport. Build passed. Screenshots are session artifacts under `/tmp/constructflow-tablet-audit/` and are not durable release evidence; MatePad hardware testing remains open under V1-TABLET. See [HUAWEI MatePad Air specifications](https://consumer.huawei.com/th/tablets/matepad-air/specs/).

Tablet/display follow-up (2026-10-18): Elevation canvases now cap backing resolution at DPR 2 and refresh on viewport resize; Family Studio 2D uses the same CSS-pixel drawing coordinates with a DPR-scaled backing store. Photo Dimension now renders annotations at the same capped DPR and redraws on container/window resize while keeping line hit tolerance in CSS-pixel terms. Its inspector stacks under the photo in coarse-pointer portrait layouts to preserve a larger working image area. In the current Chromium at DPR 1.25, Family Studio measured 393×260 CSS pixels and 492×325 backing pixels; the Photo Dimension modal opens and closes without unmounting the editor. Coarse-pointer controls now give inspector/modal/Family Studio actions at least 44 CSS-pixel touch targets and 16px form text even when the CSS viewport is wide. The compact header now retains a save-state indicator with an accessible full status label. The browser could not create WebGL contexts, so the 3D viewport now reports that limitation locally while leaving the 2D workbench mounted and usable. This is browser-environment evidence only; it does not establish 3D compatibility or touch/stylus behavior on the MatePad Air 2026.

Elevation tablet follow-up (2026-10-18): Elevation object hit regions now expand to 22 CSS px for touch and 12 px for pen (4 px for mouse), and resize grips accept touch within 22 px / pen within 18 px. Projected regions remain ordered from smallest to largest so an opening can be acquired over its host wall. Elevation zoom controls use 44 px touch targets and a wider range slider for coarse pointers. Production build passed after these changes; no new browser or MatePad gesture acceptance is claimed here, so V1-TABLET remains Partial.

Bundle follow-up (2026-10-18): Settings, type catalog, underlay calibration, project legal, photo measurement, Inspector, elevation view, Family Studio, and workbench export handlers are code-split and loaded when opened/selected. Takeoff/BOQ calculation is deferred until the quantities tab opens or an export is requested. Preact compat and Terser (two compression passes) are used for the editor; direct manipulation is loaded on first drag/resize, selection handles on first selection, transient placement ghosts/tool overlays when a tool, snap, selection box, or tape measure needs them, coordination overlays only when findings exist, and the plan renderer when the plan canvas first mounts. Pure local model and geometry packages declare `sideEffects: false` so unused barrel modules can be removed by consumers.
